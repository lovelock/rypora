# Rypora — 轻量本地 Markdown 工作区（设计文档）

- 日期：2026-11-07
- 状态：待确认
- 工作名：Rypora（目录名，可改）

## 1. 意图与为什么

Typora 的写作体验好，但文件管理弱：没有快速切换、跨文件操作别扭、一次只能盯着一篇。
Obsidian 文件管理够用，但太重：仓库索引、图谱、插件运行时都堆在渲染进程里，体感发卡。

要的是中间态：**文件系统就是仓库，编辑器专注写作，文件操作够用就好**。不做平台，不做生态。

## 2. 目标

- G1 打开一个文件夹作为工作区，左侧显示文件树，支持新建、重命名、删除、拖拽移动。
- G2 `Ctrl+P` 按文件名模糊搜索并跳转，键盘优先。
- G3 单栏 Typora 式实时渲染：光标所在行显示 Markdown 标记，其余行按排版显示。
- G4 自动保存，用户不需要关心"存没存"。
- G5 轻：冷启动 < 1.5s，常驻内存目标 < 200MB，1 万个文件的工作区可正常使用。
- G6 跨平台可构建，Linux 优先验证。

## 3. 非目标（v1 明确不做）

- 全文搜索（用户已确认后置；架构上留出口，不实现）。
- 双链、图谱、标签系统、插件、同步、协作。
- 移动端、Web 版、多窗口。
- PDF / HTML 导出。
- 表格与数学公式的所见即所得编辑（v1 只按源码显示）。
- 主题市场、自定义 CSS。
- 单文件打开、系统 MIME 关联、命令行传参：v1 必须先选择一个工作区目录。

## 4. 反目标

- 不把笔记内容存进数据库或自研格式；磁盘上的 `.md` 是唯一真相。
- 不做插件系统——这是 Obsidian 变重的起点。
- 不在每次击键时写盘。
- 不为"以后可能加"的功能提前抽象。

## 5. 约束

- 运行环境：Linux 桌面（Wayland / X11），Rust 1.99.1、Node 24、webkit2gtk-4.1 已具备。
- 单机、离线、无账号、无遥测。
- 规模假设：单工作区 1k–10k 个 Markdown 文件，单文件 < 2MB。
- 文件编码：UTF-8；保留原文件的 LF / CRLF。

## 6. 方案取舍

| 方案 | 结论 | 理由 |
|---|---|---|
| **Tauri 2 + CodeMirror 6** | **选中** | 编辑体验最接近 Typora，CM6 的 replace/widget 装饰就是实时渲染的标准做法；Rust 侧负责扫描、监听、文件操作，绕开 Obsidian 式的渲染进程负担。代价是 WebView 常驻内存。 |
| 纯 egui | 备选 | 内存和启动最轻，但富文本编辑控件、IME 边界、选区跨样式都要自己写，首版周期明显更长。 |
| gpui | 否决 | 2026 年官方已把 GPUI 开发降级为只服务 Zed 自身需求，社区 fork 不活跃；IME、原生菜单仍要手写。赌一个半托管框架不值得。 |
| Monaco | 否决 | 它是代码编辑器，只有装饰和只读 ViewZone，没有"把源码替换成可编辑渲染块"的能力，做不了单栏所见即所得。 |

## 7. 架构

```
┌─────────────────────────────────────────────┐
│ Tauri 2                                      │
│  ┌────────────────────┐  ┌────────────────┐  │
│  │ Rust core          │  │ WebView        │  │
│  │ - workspace 扫描   │◄─┤ Svelte 5 + TS  │  │
│  │ - 文件 CRUD        │  │ - 文件树       │  │
│  │ - 文件监听         │  │ - Ctrl+P 面板  │  │
│  │ - 文件名索引/匹配  │  │ - CodeMirror 6 │  │
│  │ - 配置/会话        │  │ - 实时渲染扩展 │  │
│  └────────────────────┘  └────────────────┘  │
└─────────────────────────────────────────────┘
```

- 前端：TypeScript + Vite + Svelte 5（运行时小，状态简单，不为框架打架）。
- 后端：Rust，Tauri commands + 事件。
- 通信：`invoke` 调命令；文件变更、扫描进度用 `emit` 推事件。

### 7.1 Rust 模块

| 模块 | 职责 |

| `workspace.rs` | 扫描目录、构建树、新建/重命名/删除/移动 |

| `search.rs` | 文件名索引，`nucleo-matcher` 打分与命中区间 |

依赖：`tauri`、`tauri-plugin-dialog`、`tauri-plugin-opener`、`serde`、`walkdir`、`notify` + `notify-debouncer-full`、`trash`、`nucleo-matcher`、`thiserror`。

## 8. 关键设计决策

### 8.1 工作区模型

- "打开文件夹"即工作区根目录，递归扫描 `.md` / `.markdown` / `.mdown`。
- 跳过：隐藏目录、`.git`、`node_modules`、`target`、`.obsidian`。
- 扫描在全量完成后一次性建树；10k 文件规模下无需懒加载。扫描期间显示骨架，不阻塞窗口。
- 树上排序：目录在前，同类按名称不区分大小写排序。

### 8.2 文件操作

- 新建文件 / 文件夹、重命名（`F2`，行内编辑）、删除（进系统回收站，用 `trash`）、拖拽移动。
- 跨目录移动冲突时提示，不覆盖。
- 重命名 / 移动同步更新已打开标签的路径；失败则回滚并提示。
- 删除已打开文件时关闭对应标签（若未保存完，先落盘再删）。
- 外部重命名 / 移动 / 删除已打开文件：标签按路径识别，不追踪 inode。
  - 外部删除或重命名后旧路径消失：标签标记为"磁盘上已不存在"，暂停该文件的自动保存，顶部给出"另存为 / 关闭"两条出路，**绝不把旧路径写回去**。
  - 外部移动表现为"旧文件消失 + 新文件出现"，不做自动跟随；用户可另存为到新位置。
  - 工作区根目录被整体移走时，标记工作区失效，提示重新选择目录。

### 8.3 文件名模糊搜索

- Rust 侧维护 `Vec<FileEntry { rel_path, name, last_modified }>`，工作区变化时增量更新。
- 匹配用 `nucleo-matcher`，返回分数与命中下标给前端做高亮。
- 空格分词，全部命中才算匹配；排序 = 匹配分 + 最近修改时间加权 + 路径更短优先。
- `Ctrl+P` 打开面板，`↑/↓` 选择，`Enter` 打开，`Esc` 关闭；输入即搜，150ms 内返回。
- v2 的全文搜索复用同一个面板，只换数据源，不预留抽象。

### 8.4 编辑器与实时渲染（核心）

- CM6 + `@codemirror/lang-markdown`（Lezer 增量语法树），GFM 扩展开启。
- 一个 `ViewPlugin` 在文档变化、选区变化、视口变化时，只对**可见范围**重算装饰：
  - `Decoration.mark`：粗体、斜体、删除线、行内代码、链接文字的样式。
  - `Decoration.replace`：隐藏 `**`、`_`、`` ` ``、`#`、`>`、列表标记等。
  - `Decoration.replace({ block: true, widget })`：图片、分割线、代码块、任务复选框。
  - `EditorView.atomicRanges`：让光标跳过被隐藏的标记。
- **光标行规则**：光标所在行不做替换，显示原始 Markdown，方便改语法；离开该行即渲染。这是 Typora / Obsidian live preview 的共同做法，也是"实时渲染"的全部含义。
- 块级 widget 只读，点击后把光标放进对应源码区间，切回编辑态。
- 性能：装饰只算 `view.visibleRanges`；语法树用增量解析；单次输入到重绘目标 < 16ms。
- IME：替换区间不得覆盖正在合成的文本；中文输入作为验收项，不是"以后再说"。
- 图片：相对路径按当前文件所在目录解析，经 Tauri asset 协议或按需读字节生成本地 URL；不加载远程图片。
- 链接：非光标行上 `Ctrl/Cmd + 点击` 才触发，避免和放光标冲突。相对 `.md` 在当前窗口新标签打开，`#anchor` 滚动到对应标题；`http(s)` 交给系统浏览器；其他相对路径交给文件管理器。光标行处于源码模式时链接不响应点击。
- 代码块高亮：用 CM6 自带的 `@codemirror/language-data` 按需加载语言包（Vite 分块，离线可用），渲染时用 `highlightTree` 生成带 class 的 DOM；未知语言退化为纯文本。v1 不引入 Shiki / Prism 这类第二套高亮引擎。

v1 支持的 Markdown 子集：标题、段落、粗体/斜体/删除线、行内代码、围栏代码块（语法高亮）、链接、图片、引用、有序/无序列表、任务列表、分割线。表格和公式按源码显示。

### 8.5 自动保存

- 最后一次编辑后 400ms 去抖写盘；切换标签、失焦、关窗时立即落盘。
- 原子写：临时文件 + rename，避免半截文件。
- 内容未变化不写；保留原换行符。
- 外部修改冲突：缓冲区干净则自动重载；有未落盘修改则显示冲突条，让用户选"保留我的 / 载入磁盘版本"。

### 8.6 文件监听

- `notify` 递归监听 + 250ms 去抖，事件合并后一次性推给前端。
- 自身写入用"路径 + 时间窗"抑制，避免回环刷新。
- 监听溢出或目录被删时，降级为手动刷新按钮，不崩。

### 8.7 标签与会话

- 打开的文件以标签形式存在；每个标签保存自己的 `EditorState`（文档、选区、撤销历史），共用一个 `EditorView`，切换时 `view.setState()`。
- 会话持久化：上次工作区、打开的标签与顺序、当前标签、侧边栏宽度、主题、字号。
- 启动时恢复上次工作区；目录不存在则回退到空状态。
- 标签恢复是**懒加载**：只还原路径、顺序、光标与滚动位置，内容在首次激活时读取；上次运行期间已被删除的文件直接丢弃并提示，不阻塞启动。

### 8.8 主题与排版

- 亮 / 暗两套，跟随系统，可手动切换。
- CSS 变量 + CM6 主题，正文最大宽度约 760px，居中；字体、行高、段间距以写作为准。
- 界面不追求花哨，目标是"打开就能写"。

## 9. v1 交付范围

1. 打开 / 切换工作区，文件树与 CRUD。
2. 标签页、会话恢复。
3. `Ctrl+P` 文件名模糊搜索。
4. 上述 Markdown 子集的实时渲染，中文输入正常。
5. 自动保存 + 外部变更监听。
6. Linux 下可打包运行（`.deb`，AppImage 作为附加）。

## 10. 里程碑

| 里程碑 | 内容 | 验收 |
|---|---|---|
| M1 骨架 | Tauri + Svelte + CM6，打开单个文件可编辑 | 能跑起来，能打字 |
| M2 工作区 | 扫描、文件树、CRUD、标签 | 建/改/删/移动后树正确 |
| M3 搜索 | 文件名索引 + `Ctrl+P` | 1 万文件下输入到出结果 < 150ms |
| M4 渲染 | 实时渲染扩展 + widget + 快捷键 | 列表/代码块/图片/中文输入通过 |

| M6 打包 | Linux 安装包 | 干净机器可安装运行 |

每个里程碑单独可运行，不一次性合入。

## 11. 风险

- **CM6 装饰的边角**：嵌套列表、块级 widget 与选区、IME 合成区间。缓解：先做行内 + 标题 + 代码块，表格/公式明确不做。
- **WebKitGTK 内存波动**：目标写 200MB 而非 100MB，避免虚假承诺；打包后实测。
- **文件监听风暴**：大目录 + 编辑器批量写入会触发大量事件，靠去抖 + 自身写入抑制。
- **Linux 打包依赖**：webkit2gtk 版本、AppImage 的 FUSE 依赖；以 `.deb` 为主。

## 13. 为什么这样取舍

- 选 Tauri 而不是 egui：用户要的是"像 Typora 的排版"，CM6 已经把这套模式验证过（Obsidian live preview），自研编辑控件是数倍工作量。
- 选文件名搜索而不是全文：先把"找得到、打得开、写得顺"做扎实；全文搜索是独立模块，后加不返工。
- 不做插件 / 图谱 / 双链：这些正是 Obsidian 变重的来源，也是本项目的反目标。
